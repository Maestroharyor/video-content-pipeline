Fair enough
Yes, there are other
kinds of pagination
Offset / limit
Simple, and fine on a small table that barely moves.
Page numbers
When people genuinely need to jump to page 12.
Keyset / seek
The SQL technique a cursor is usually built on top of.
Cursor
Opaque pointer to the last row. Best default for feeds.
Each one has a job. This tip is about the one that scales quietly.
Pick per list, not per codebase.
Common mix-up
A cursor is not
infinite scroll
Cursor pagination
A backend contract. How the server decides which rows to return next.
Infinite scroll
A frontend pattern. How the screen decides when to ask for more.
One feeds the other. They are not the same thing.
You can build infinite scroll on offsets. It will just get slower and start repeating itself.
Server decides what. Client decides when.
Put together
Cursor on the back,
infinite scroll on top
1  ·  User scrolls near the bottom of the list
2  ·  Client sends the cursor it was given last time
3  ·  Server seeks to that row and returns the next 20
4  ·  Client appends them and stores the new cursor
repeat forever
Same UX as before, far less work per request, and no drift as the data changes.
The loop costs the same on row 20 as it does on row 20,000.
Why the UX improves
The list stays fast
however far you scroll
